## 畫面時序

---

### 🎬 [00:00 – 00:15] 開場：問題陳述

**畫面**：黑底白字投影片（或直接口說 + 靜態圖）

```
台灣每年颱風季，社工師面對數百筆關懷名單
卻不知道誰、在哪裡、面對多大的風險

EcoPredict — 用機器學習為社工師找到最需要幫助的人
```

**旁白**：
> 台灣每逢颱風豪雨，第一線社工師需要在短時間內聯繫數百位獨居長者與行動不便者，
> 卻缺乏量化依據決定優先順序。
> EcoPredict 結合中央氣象署即時資料與機器學習，
> 讓社工師在颱風登陸前 24 到 48 小時，就能鎖定最高風險的社區與對象。

---

### 🎬 [00:15 – 00:45] Dashboard 地圖畫面

**操作**：
1. 在瀏覽器打開 `https://ecopredict.pages.dev`（或本地 `http://127.0.0.1:8080`）
2. 等待地圖完全載入（深色台灣地圖 + 彩色圓點）
3. 用滑鼠滾輪放大到台灣北部山區，讓紅色（極高風險）圓點清楚可見

**旁白**：
> 這是 EcoPredict 的即時監測 Dashboard。
> 地圖上每一個圓點代表一個氣象觀測站。
> 顏色系統與台灣 NCDR 災害警戒色碼對應：
> 綠色是低風險、黃色是中風險、橙色是高風險、紅色是極高風險。
>
> 右側告警清單顯示目前所有超過高風險門檻的站點，依風險分數排序。
> 可以看到，受到颱風白海豚的影響，北部山區和台中和平區出現大量紅色標記。

**畫面重點**：
- 畫面左側：台灣北部山區密集的紅色圓點（陽明山系）
- 畫面右側：告警清單，第一條：「稍來 — 極高風險 98%」

### 🎬 [00:45 – 01:30] 點擊高風險社區

**操作**：
1. 點擊陽明山/北投區的一個紅色圓點（例如「小油坑」站）
2. 等待彈窗出現：顯示站名、風險等級徽章、三格雨量數值
3. 讓 Chart.js 折線圖完全渲染（未來 48h 降雨機率）
4. 移動滑鼠讓評審看到 tooltip 顯示數值

**旁白**：
> 點擊任何一個站點，會看到這個社區的詳細資訊卡。
>
> 以台北市北投區的「小油坑」測站為例：
> 目前 1 小時雨量 20mm、24 小時累積 20mm、過去 3 天累積 316mm。
>
> 下方折線圖是未來 48 小時的降雨機率預報，
> 來自中央氣象署鄉鎮天氣預報 API。
> 可以看到明天清晨開始降雨機率攀升到 60% 以上。
>
> 右下角顯示這個縣市共有 5 位弱勢關懷對象列入系統名單。

**畫面重點**：
- 彈窗：「小油坑」、「極高風險」紅色徽章
- 雨量三格：1h=20mm、24h=20mm、3天=316mm
- 折線圖：明顯的 PoP 上升趨勢
- 右下角「👥 5 人」關懷徽章

### 🎬 [01:30 – 02:15] 告警清單與關懷名單

**操作**：
1. 滑到右側告警清單（或在手機上點 🚨 FAB 按鈕開啟）
2. 點擊「臺北市」的告警條目，地圖自動飛到北投區
3. 切換到終端機，執行：
   ```bash
   python src/alert_dispatcher.py 2>/dev/null | head -60
   ```
4. 或者直接開啟 `reports/alert_report.json`，展示 JSON 結構

**旁白**：
> 右側告警清單即時更新，顯示所有超過門檻的站點。
>
> 最關鍵的功能是：系統會自動比對弱勢關懷名單。
>
> 以台北市為例，12 個站點觸發極高風險告警，
> 系統找到 5 位同縣市的關懷對象，其中 4 位是「優先通知」等級——
> 包括使用輪椅的獨居長者陳B女士、
> 聽力受損無法接收廣播的王D奶奶、
> 以及視力受損夜間需協助撤離的李K大哥。
>
> 系統自動產生建議行動清單：
> 立即啟動撤離程序、安排接送服務、通知消防局待命。
>
> 在正式部署中，這份 alert_report.json 會作為 LINE Bot 的輸入，
> 自動推播給社工師手機，讓她不用滑手動名單，直接知道要打哪幾通電話。

**畫面重點**（選其一展示）：
- 方案 A：Terminal 輸出中 `★ [REG-002] 陳B女士 — 北投區 [獨居, 行動不便]`
- 方案 B：VS Code 打開 `alert_report.json`，展示 `priority_list` 陣列結構

### 🎬 [02:15 – 03:00] 模型評估與回測

**操作**：
1. 打開 `reports/feature_importance.png`（深色背景特徵重要性圖）
2. 打開 `reports/model_comparison.csv`（或用 Python 快速顯示）
3. 執行回測輸出展示（或展示預先截圖）

**旁白**：
> 我們訓練了三個模型：邏輯迴歸、決策樹、隨機森林。
>
> 由於這是不平衡資料——淹水事件只佔 3.6%——
> 我們以 AUC-ROC 和 F1 為主要評估指標，而不是 Accuracy。
>
> 隨機森林以 AUC-ROC 0.997、Precision 1.0 勝出。
>
> 這張特徵重要性圖顯示，模型最看重的特徵是「3 天累積雨量」——
> 這符合土壤物理學：土壤水分飽和度才是決定土石流風險的關鍵，
> 而不只是當下的瞬間雨量。
>
> 我們用颱風白海豚事件做回測：
> 模擬站在颱風登陸前 48 小時，用當時能取得的資料去預測。
> 結果是：Precision = 1.0——
> 模型預測為「高風險」的 14 個站點，100% 確認在颱風後受到大量降雨。
> 沒有任何假陽性，代表每一個告警都有真實依據。

**畫面重點**：
- `feature_importance.png`：rain_3days 是最高的橫條
- 模型比較表：RandomForest 的 1.000 Precision 和 0.997 AUC 清楚可見
- 回測輸出：`Precision : 1.0000` 字樣
