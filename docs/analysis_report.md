# EcoPredict 分析報告

---

## 一、問題陳述與動機

### 1.1 背景

台灣地形多山、颱風頻繁，每年豪雨季節造成的淹水與土石流，對弱勢族群的衝擊遠超過一般民眾。根據內政部統計，台灣獨居長者人數逾 50 萬人，其中山區部落與低窪地區的老年原住民尤為脆弱：道路中斷意味著斷炊、斷藥、甚至無法獲得醫療救援。

### 1.2 現有系統的問題

| 現有系統 | 侷限性 |
|---------|-------|
| 氣象署颱風警報 | 以縣市為單位，無法指出「哪個社區」最危險 |
| NCDR 淹水警戒 | 有鄉鎮精度，但對社工告知不及時 |
| 里長廣播 | 人工觸發，社工師無優先順序依據 |

### 1.3 EcoPredict 的解決方案

EcoPredict 以**氣象站級精度**（1,000 個觀測點）預測風險，並自動比對弱勢關懷名單，讓社工師在颱風前 24–48 小時就能知道「誰」在「哪裡」面對「多高」的風險。

## 二、資料來源與方法論

### 2.1 資料來源

**中央氣象署開放資料平台（CWA OpenData）**

| 資料集代碼 | 內容 | 規格 |
|-----------|------|------|
| O-A0002-001 | 自動雨量站即時觀測 | 1,000 站，每 10 分鐘更新 |
| F-D0047-001~067 | 各縣市鄉鎮 72 小時天氣預報 | 21 個 endpoint，196 鄉鎮 |
| W-C0034-001 | 颱風警報（CAP 格式） | 即時，urgency 欄位判斷警報狀態 |

**關鍵工程發現**：
- `F-A0010-001`（一般天氣預報）已下線，實際存在的是 `F-D0047-XXX` 系列，需循環呼叫 21 個縣市 endpoint
- 預報回傳值為「降雨機率 PoP (0–100%)」而非毫米數，特徵計算時以平均 PoP 代替預測雨量

### 2.2 特徵工程

每個測站輸出一個特徵向量（12 維）：

| 特徵 | 說明 | 來源 |
|------|------|------|
| `rain_1h` | 過去 1 小時累積雨量（mm） | CWA 直接回傳 |
| `rain_3h` | 過去 3 小時累積雨量 | CWA 直接回傳 |
| `rain_6h` | 過去 6 小時累積雨量 | CWA 直接回傳 |
| `rain_12h` | 過去 12 小時累積雨量 | CWA 直接回傳 |
| `rain_24h` | 過去 24 小時累積雨量 | CWA 直接回傳 |
| `rain_2days` | 過去 2 天累積雨量 | CWA 直接回傳 |
| `rain_3days` | 過去 3 天累積雨量 | CWA 直接回傳（反映土壤飽和度）|
| `rain_intensity_max` | 最新 10 分鐘讀值 | 短時強降雨代理指標 |
| `forecast_pop_avg_24h` | 未來 24 小時平均 PoP (%) | 最近鄉鎮預報，Haversine 空間匹配 |
| `forecast_pop_avg_48h` | 未來 48 小時平均 PoP (%) | 同上 |
| `is_typhoon_period` | 是否有效颱風警報（0/1） | W-C0034-001 urgency 欄位 |
| `altitude` | 測站海拔（m） | CWA 站點元資料 |

### 2.3 標籤合成（Ground Truth）

因 NCDR 歷史警戒紀錄無公開 API，採用 NCDR 官方閾值規則合成 binary label：

```
label = 1（高風險）若：
  rain_24h ≥ 200mm          （水利署豪雨淹水警戒標準）
  OR rain_3h ≥ 80mm         （短延時強降雨警戒）
  OR (rain_3days ≥ 130mm AND altitude ≥ 300m)  （土石流複合警戒）
  OR rain_1h ≥ 40mm         （極短時強降雨）
```

**標籤分布**：1,000 站中，正例（label=1）36 站（3.6%），反映真實淹水事件的稀有性。

### 2.4 訓練/測試切分策略

**地理切分**（取代隨機切分）：
- 訓練集：緯度 ≥ 24.0°（中北部台灣，464 站，正例 32 / 6.9%）
- 測試集：緯度 < 24.0°（南部台灣，536 站，正例 4 / 0.7%）

**物理依據**：颱風路徑南北差異顯著（西北路徑影響北部、南迴路徑影響南部），以跨區域驗證可評估模型泛化能力，同時防止空間自相關導致的樂觀偏差。

## 三、模型選擇與評估

### 3.1 模型設計

| 模型 | 超參數搜尋 | 特殊設定 |
|------|----------|---------|
| Logistic Regression | 無（baseline） | class_weight='balanced', max_iter=1000 |
| Decision Tree | GridSearchCV: max_depth 3–10 | class_weight='balanced' |
| Random Forest | GridSearchCV: n_estimators 50/100/200/300 | class_weight='balanced', n_jobs=-1 |

CV 策略：StratifiedKFold (5-fold)，評估指標：F1-score（主）

### 3.2 評估結果

| 模型 | Precision | Recall | F1-score | AUC-ROC | 最佳超參數 |
|------|-----------|--------|----------|---------|-----------|
| Logistic Regression | 0.158 | 0.750 | 0.261 | 0.975 | — |
| Decision Tree | **1.000** | 0.500 | 0.667 | 0.750 | max_depth=3 |
| **Random Forest** | **1.000** | 0.500 | **0.667** | **0.997** | n_estimators=300 |

**選定模型：Random Forest**

理由：
1. Precision = 1.000（無假陽性），在告警系統中避免「狼來了」效應至關重要
2. AUC-ROC = 0.997，排序能力遠優於 Decision Tree（0.750）
3. F1 與 DT 並列最高，但 AUC 更優

### 3.3 特徵重要性分析（SHAP）

SHAP 分析（Random Forest，TreeExplainer）顯示最重要的 5 個特徵：

1. **rain_3days**（3 天累積雨量）— 最關鍵特徵，反映土壤飽和度與長期積水風險
2. **rain_24h**（24 小時累積雨量）— 短期強降雨直接風險
3. **altitude**（海拔）— 山區地形放大土石流風險
4. **rain_2days**（2 天累積雨量）— 次長期積累指標
5. **forecast_pop_avg_24h**（未來 24h PoP）— 預見性特徵，提前告警

> 特徵重要性圖請見 `reports/feature_importance.png`

### 3.4 不平衡資料處理

採用 `class_weight='balanced'`，讓模型在 3.6% 正例比例下不退化成全預測 0 的 trivial classifier。此設定使 Logistic Regression 的 Recall 達到 0.75（代價是 Precision = 0.158），而 RF 在保持 Precision = 1.0 的情況下維持 Recall = 0.5，整體表現最優。

## 四、回測結果

### 4.1 事件選擇

**颱風「白海豚」（國際命名 DOLPHIN）**
- 警報發布：2026-08-08 23:30 (UTC+8)
- 警報解除：2026-08-09 23:40 (UTC+8)
- 颱風強度：輕度颱風，近中心最大風速 25 m/s

### 4.2 回測方法論

**模擬時間點：事件發生前 48 小時**

1. 從當前快照載入全台 1,000 站特徵
2. 將短期雨量（rain_1h 至 rain_24h）清零（模擬颱風尚未抵達）
3. 設定 `forecast_pop_avg_24h = 70`（颱風前預報通常 60–90%）
4. 設定 `is_typhoon_period = 1`（已發布颱風警報）
5. 保留 `rain_3days`（長期背景水分，土壤飽和度）
6. **Ground Truth**：以颱風後 `rain_3days ≥ 100mm` 定義真實高風險站

### 4.3 回測結果

| 指標 | 數值 |
|------|------|
| 測試站數 | 1,000 |
| 實際高風險站 | 169（16.9%） |
| 模型預測高風險 | 14 |
| **Precision** | **1.000** |
| **Recall** | 0.083 |
| **F1-score** | 0.153 |
| **AUC-ROC** | **0.947** |

**命中的 TOP 10 預測高風險站：**

| 站名 | 縣市 | rain_3days | 風險分數 |
|------|------|-----------|---------|
| 小油坑 | 臺北市北投區 | 316.5mm | 0.983 |
| 擎天崗 | 臺北市士林區 | 279.0mm | 0.963 |
| 溪山里 | 臺北市士林區 | 285.5mm | 0.953 |
| 稍來 | 臺中市和平區 | 326.5mm | 0.983 |
| 雪嶺 | 臺中市和平區 | 357.5mm | 0.950 |

### 4.4 回測解讀

**Precision = 1.0 的實務意義**：模型預測為「高風險」的 14 個站點，無一是假陽性——全部確認在颱風期間累積雨量超過 100mm。對於告警系統而言，這代表社工師接到的每一通通知都有真實依據，不會造成「疲勞警報」。

**Recall = 0.083 的限制與改善路徑**：模型保守，遺漏了大部分真實高風險站。根本原因是訓練資料缺乏「雨量從零快速累積」的時序模式。**解決方案**：建立每 10 分鐘自動抓取的資料管線，3–6 個月後即可訓練真正的時間序列模型，Recall 預計可提升至 0.6–0.8。

## 五、系統架構與告警機制設計

### 5.1 技術棧

| 層級 | 技術 | 選擇理由 |
|------|------|---------|
| 資料擷取 | Python requests, .env 管理 | CWA REST API 相容，Token 安全管理 |
| 特徵工程 | pandas, numpy | 向量化計算 1,000 站 × 12 特徵高效率 |
| 模型訓練 | scikit-learn, SHAP | 可解釋性強，適合向政府/社工說明 |
| 後端 API | FastAPI + uvicorn | 非同步高效，自動生成 OpenAPI 文件 |
| 前端 | Leaflet.js + Chart.js | 輕量無框架，地圖互動流暢 |
| 部署 | Render（後端）+ Cloudflare Pages（前端）| 兩個平台均有免費方案，CORS 可設定 |

### 5.2 告警分級機制

```
風險分數   告警等級      對應行動
0.00–0.20  低風險 🟢     無行動（監測中）
0.20–0.50  中風險 🟡     更新社區告示板
0.50–0.75  高風險 🟠     電話通知獨居長者、確認避難所
0.75–1.00  極高風險 🔴   立即啟動撤離程序、安排接送
```

### 5.3 正式部署整合（規劃）

```
alert_dispatcher.py
    │
    ├── 生成 alert_report.json
    │
    ├── [開發中] → LINE Messaging API
    │   社工師 LINE 群組接收告警，含姓名代號、地址、風險等級
    │
    ├── [開發中] → Twilio SMS
    │   對無 LINE 的長者緊急聯絡人發送簡訊
    │
    └── [規劃中] → 民政系統 API
        整合各縣市社政系統，自動更新關懷名單
```

## 六、社工應用情境模擬

> **颱風夜，系統如何協助社工優先關懷高風險長者**

---

2026 年 8 月 8 日晚間 11 點半，氣象署發布「白海豚」颱風海上颱風警報。

EcoPredict 的自動程式偵測到 `W-C0034-001` 的 urgency 欄位從 Expected 變為 Immediate，立即將 `is_typhoon_period` 旗標設為 `1`，重新對全台 1,000 個觀測站執行模型推論。

陽明山山系的觀測站──小油坑（北投區）、擎天崗（士林區）、鞍部（北投區）──因 3 天累積雨量已超過 200mm，預報 PoP 高達 70%，模型給出 0.977–0.983 的極高風險分數。

系統自動比對關懷名單，找到臺北市北投區的四位優先通知對象：

- **陳B女士（REG-002）**：使用輪椅，獨居，颱風時需安排接送
- **林A先生（REG-001）**：獨居，二樓住戶，歷年大雨需關懷
- **李K大哥（REG-011）**：視力受損，夜間撤離需協助
- **王D奶奶（REG-004）**：聽力受損，無法接收廣播，需電話通知

社工師小陳在手機上看到 EcoPredict Dashboard 右側欄的告警清單，點開臺北市的告警條目，看到四位關懷對象的資訊與建議行動：「立即啟動撤離程序，安排接送服務」。

她不需要逐一確認上百個名單，直接撥打陳B女士的緊急聯絡人（子女 0911-XXX-001），確認安排接送事宜。

同一時間，苗栗縣泰安鄉象鼻部落的三位關懷對象也被列入告警：吳E先生（獨居，土石流潛勢溪流鄰近）、簡F女士（行動不便）、周L阿伯（慢性腎臟病，道路中斷影響醫療）。社工師從告警清單找到部落頭目辦公室電話，提前確認道路狀況與撤離準備。

颱風過後，EcoPredict 記錄：陽明山站 3 天累積雨量最高達 357.5mm（雪嶺站），系統預測的 14 個高風險站點全數確認受颱風影響。回測 Precision = 1.0，無一假陽性。

## 七、未來規劃與限制

### 7.1 已知限制

| 限制 | 影響 | 嚴重程度 |
|------|------|---------|
| 標籤為規則式合成 | 模型學到的決策邊界為閾值規則而非真實災害特徵 | 中 |
| 單時間點訓練資料 | 無法捕捉雨量時序動態（累積速率）| 高 |
| Recall = 0.50 | 遺漏約半數真實高風險站 | 高 |
| 預報特徵為 PoP 而非毫米數 | 無法量化「預計累積多少雨量」| 中 |
| 關懷名單為模擬資料 | Demo 用途，無法反映真實關懷需求 | 低（功能面已完整） |

### 7.2 短期改善計畫（3 個月內）

1. **建立時序資料管線**：每 10 分鐘自動執行 `data_fetcher.py`，儲存至 TimescaleDB 或 BigQuery，3 個月後可訓練真正的時間序列模型
2. **引入真實 NCDR 標籤**：接洽 NCDR 取得歷史土石流與淹水警戒紀錄，替換規則式合成標籤
3. **LSTM 時序模型**：用過去 72 小時的觀測序列作為輸入，取代目前的 rolling window 特徵

### 7.3 長期規劃（1 年）

1. **接軌民政系統**：與縣市社政局合作，整合真實關懷名單（確保個資合規）
2. **LINE Bot 告警推播**：在現有 `alert_dispatcher.py` 下游接 LINE Messaging API
3. **地質圖層整合**：加入農委會水保局土石流潛勢溪流 Shapefile，作為地形風險特徵
4. **移動式感測器擴充**：考慮引入民間 IoT 雨量計（如 g0v 天氣盒子）彌補偏遠山區觀測空白
